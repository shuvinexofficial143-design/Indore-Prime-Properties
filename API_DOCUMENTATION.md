# API and server actions
/api/health: liveness. Authentication and logout: same-origin, hashed server sessions, secure cookies. Owner/agent/customer server guards.
Media upload: owner-only tenant property, private S3-compatible storage, allowed signatures and 3 MB limit. Private staging, review/publish; media read restricted to authorized owner or published demo, short video range playback. Separate document access grants, review, expiry and audit; no private owner fields in public listing. /api/saved: signed-in customer saved property persistence.
Property CRUD, CSV import/export, team provisioning, account security, CRM, visit booking/cancellation, follow-ups, studio review, branding and simulation controls use role-scoped actions. Public enquiry/visit require fictional consent/contact, rate limits and transactional persistence; random receipt exposes only limited details. Sandbox session uses isolated data with expiry.
POST /api/assistant/interpret: same origin, signed in, opt-in per request, external feature flag and key, bounded text, daily usage reservation before request. Strict allowlisted filters, no CRM or property data sent, no provider-generated listing claims. Local fallback on error. Meshy owner actions require source permission and charge consent; explicit submit/refresh/import, no automatic retry on unknown charge status. Private GLB review before publish.
External communications are not enabled; internal automation is simulation only. See source and deployment guide for current endpoint/operation details.
